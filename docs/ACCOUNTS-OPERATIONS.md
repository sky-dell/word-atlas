# 账号、会员与数据运维

> 本文保留为早期账号阶段记录。当前已改为纯免费账户、邮箱验证码及右上角下拉菜单，请使用 [最新运维说明](./FREE-ACCOUNTS-OPERATIONS.md)，不要按历史会员开通/到期流程操作。

本机生产目录 `/data/word-atlas`；账号服务使用 Node24，数据库与密钥不进入静态发布目录。新账号是普通账号，会员由管理员明确授权，管理员角色只通过本机 CLI 建立。

打开页面先选择「游客进入／账户登录」，已有有效登录则直接进入。游客选择仅在当前标签页内临时记住，不删除已保存的学习资料。右上角使用账户图标；进入后可在「账号与会员」浮层注册、退出、改密及管理会员数据，不再嵌入「我的」正文。已登录的旧 `#/account` 链接可直接打开浮层，未登录则进入账户登录入口。详情见 `ENTRY-MODES.md`。

## 首次初始化与管理员

首次部署执行初始化（不生成默认用户或密码）：

```bash
sudo runuser -u word-atlas -- /opt/nodejs/node-v24.22.1-linux-x64/bin/node /data/word-atlas/scripts/admin.mjs init
```

生产服务要求数据库已存在且正确初始化；文件缺失、空库、损坏或未知结构时启动失败，不会悄悄替换成一个新库。

在 SSH 本地交互终端创建管理员，密码不回显、不放入参数、环境变量或聊天：

```bash
sudo runuser -u word-atlas -- /opt/nodejs/node-v24.22.1-linux-x64/bin/node /data/word-atlas/scripts/admin.mjs create-admin --username owner_admin
```

用户名可换成未被使用的 3–32 位字母、数字、下划线，密码为 8–128 字符，须包含大写字母、小写字母、数字和符号。创建后访问 HTTPS 的 `#/account` 登录，再进入 `#/admin`。管理员与会员分开：管理员不会自动获得会员身份，可在管理页给自己开通会员。

管理员忘记密码时，仅在本机执行 `reset-admin --username owner_admin`，交互设置新密码并撤销该管理员的所有会话。不能通过网页重置其他管理员。普通用户重置由管理员生成短期一次性凭据，再通过已有可信渠道手工交付，不自动发短信或邮件。

## 邮件服务管理

`#/admin` 的“邮件服务”支持任意 SMTP 服务商，不依赖固定域名或固定邮箱。配置字段为 SMTP 主机、端口、加密方式、登录账号、SMTP 授权码、发件地址和发件人名称。加密方式只支持隐式 TLS 与 STARTTLS；两者都强制校验证书并使用 TLS 1.2 以上。SMTP 主机必须解析到公网地址，回环、私网、链路本地、组播和未指定地址都会被拒绝。不接受明文 SMTP，也不支持 Resend、SendGrid 等 HTTP API 邮件服务。

当前 SMTP 服务卡片只展示主机、端口、加密方式、登录账号、发件地址、发件人名称和是否已配置。SMTP 授权码为只写字段，浏览器、状态接口、审计与日志都不会返回或保存其明文副本；管理员不能查看已保存的授权码。首次配置必须录入授权码；已有配置时留空表示保留原授权码，更换服务商或凭据时才录入新值。

“测试连接”和“保存配置”都会要求重新输入当前管理员密码，并经过现有 HTTPS、可信 Origin、CSRF、短时重新认证和独立限流。测试只验证候选配置，不改变当前服务；保存需要受限本地助手可用。助手通过 `/run/word-atlas-admin/control.sock` 的固定 `mail-save` 动作，在 root 目录内以临时文件、fsync 和原子重命名更新 `/etc/word-atlas/mail.env`。文件必须为 root 所有、普通文件且权限 0600；目录不得由其他用户写入，符号链接和不安全权限会被拒绝。更新时保留现有验证码 HMAC 密钥。

测试成功后点击保存，助手先完成原子持久化，Web 进程随后替换内存中的 SMTP 运行时，无需重启服务。状态卡与运行概览中的“邮件服务”状态会随动态配置更新。若助手不可达，读取当前状态仍可用，但保存会返回通用服务错误，不会泄露服务商诊断或授权码。

更换服务商时，在“邮件服务”中填写完整的新主机、端口、安全模式、登录账号、发件地址和发件人名称；凭据未变化可留空，服务商签发新授权码时再录入。先测试连接，再保存。若管理页或助手不可用，可从 root 交互终端执行下方回退命令；不能把授权码放入参数、环境变量或管道：

```bash
sudo /usr/local/bin/node /data/word-atlas/scripts/configure-mail.mjs
```

已有配置时，只有明确替换才给该命令添加 `--replace`；授权码留空会保留原值。CLI 只写文件，不会通知正在运行的 Web 进程，因此用 CLI 修改后需要重启服务才能加载。

## 数据边界

| 数据 | 保存位置 | 生命周期及权限 |
| --- | --- | --- |
| 注册账号、密码哈希、管理员角色 | SQLite users | 持久保存；无明文密码；只能服务端决定角色 |
| 会员授权 | users 的 permanent / expires_at | 永久标志与限期时间分开；到期和取消立即停止新云写入，不删除学习记录 |
| 登录会话 | Secure/HttpOnly cookie + DB 哈希 | 最长 7 天；退出/改密/禁用撤销；重启不会自动退出 |
| 匿名 CSRF 会话 | cookie + DB | 1 小时；不是注册账号 |
| 密码重置凭据 | DB 哈希 | 30 分钟、一次使用；再次生成替换旧凭据；改密/禁用失效 |
| 管理操作二次验证 | 当前会话的 reauth_at | 5 分钟有效；授权操作仍逐次校验当前角色和账号状态 |
| 已完成学习进度、收藏、设置 | 按账号隔离的 IndexedDB / localStorage | 本地优先；退出不删除；游客保持原来的命名空间，导入游客数据需明确选择 |
| 未完成的学习会话 | 当前账号本机存储 | 本机接续；从云同步及用户导出快照中排除，不承诺跨设备接续半道题 |
| 云端学习快照 | SQLite progress | 会员每用户每词库独立；CAS 版本控制，不静默覆盖双设备冲突 |
| 用户云端备份 | SQLite backups | 每词库最近 3 份；到期后仍可下载自己的既有备份 |
| 恢复前安全副本 | 当前账号 localStorage | 每词库一份，下一次恢复前备份覆盖；不作为异地容灾 |
| 整库运维备份 | `/var/lib/word-atlas/backups` | 每晚一致性备份，保留最近 7 份；目录 0700、文件 0600；同主机备份 |
| 管理操作记录 | SQLite audit | 持久保留操作者、目标和前后授权；不含密码、会话或重置 token、学习快照正文 |

过期会话、重置凭据与限流记录会在后续 API 请求时清理；即使尚未物理清理，过期时间检查已禁止使用。临时凭据的有效期不会改变永久账号和学习快照的保留。

## 传输、隔离与存储限额

- HTTP80 继续提供游客学习和旧数据导出；注册登录只在有效 HTTPS443 上启用。HTTP/HTTPS 浏览器存储互相隔离，旧 HTTP 用户应先在「我的」导出 JSON，再去 HTTPS 登录目标账号后导入。
- API 不被 Service Worker 缓存；账号身份不从备份或 localStorage 信任。切换账号会取消旧网络请求、切换命名空间，服务端用 cookie 决定所有者并核对预期账号头。
- 单次云请求最多 10 MiB，普通账号/管理请求最多 16 KiB，整体最多同时读取 4 个请求体；密码计算最多并行 2 个。
- 每账号全部云快照和备份默认 40 MiB；全站云数据默认 512 MiB。更新快照及保留备份时按实际增量检查，超过上限不删除原数据。由 `/etc/word-atlas/environment` 的 `ACCOUNT_QUOTA_BYTES`、`CLOUD_QUOTA_BYTES` 调整；上调前要给数据库与 7 份整库备份预留磁盘。
- 额外数据按白名单、项数、大小和结构校验。恢复时替换当前账号的附加数据；配额写入失败时回滚已写的附加记录，不推进主学习进度。系统级存储损坏或浏览器强制清理仍需要用户自己的导出备份。
- 云同步先等待本机存储提交成功；本机保存失败时不上传、不记录已同步。用户修改与远端版本同时变化时，先提供本机备份，再由用户明确选择版本。

浏览器账号命名空间不是磁盘加密；有本机操作系统权限、浏览器开发工具权限或同源脚本执行权限的人仍可能读取浏览器数据。页面离线后可继续当前本机学习；完全离线重载时，身份无法验证则回到游客入口，不展示其他账号资料。

## 运维备份与灾难恢复

手动一致性备份：

```bash
sudo runuser -u word-atlas -- /opt/nodejs/node-v24.22.1-linux-x64/bin/node /data/word-atlas/scripts/admin.mjs backup
```

系统定时器：`word-atlas-database-backup.timer` 每晚执行；`word-atlas-certificate-renew.timer` 每天两次检查证书续期。证书部署钩子使用 root 所有的 `/etc/word-atlas/tls`，服务账号只有读取权限，不能替换续期目标目录。

恢复整库是管理员明确操作，先停止服务，保全原数据库及其 WAL/SHM 文件，再从已验证的一致性备份复制到配置路径，所有者 word-atlas、权限 0600。不得在线只复制 `.sqlite` 而忽略 WAL。恢复旧备份也会恢复旧的临时会话记录，因此在重新启动服务前执行：

```bash
sudo runuser -u word-atlas -- /opt/nodejs/node-v24.22.1-linux-x64/bin/node /data/word-atlas/scripts/admin.mjs invalidate-sessions
```

该命令清除所有临时会话与重置凭据，保留账号、会员和学习数据，要求所有用户重新登录。常规服务重启不需要执行它。

新版本构建发布只更新程序和静态文件，不能覆盖 `/var/lib/word-atlas`。原源码/静态发布可回退；账号库单独备份和校验，程序回退不得自动回滚用户新产生的学习数据。
