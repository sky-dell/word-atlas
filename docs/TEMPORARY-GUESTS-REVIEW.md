# 临时游客与用户名检查 · 2026-11-01

## 已批准规则

Cookie仅保存临时凭证，独立SQLite库保存短期学习记录。闲置24小时失效，创建后最长7天；查询与后台轮询不续期。启动补扫、每5分钟清理，所有接口即时拒绝过期身份。

游客不是正式账户，不新增users记录、不授予账户权限；游客Cookie与CSRF独立。浏览器只保留学习数据内存，不新增游客学习记录到localStorage或IndexedDB。旧本机游客资料不删除、不自动导入。

## 运维

- `/var/lib/word-atlas/guests.sqlite`，0600，服务以word-atlas运行；仅占现有主机资源，无新增付费订阅、无新Redis服务。
- 当前服务默认根据accounts.sqlite所在目录创建独立guests.sqlite，可用`GUESTS_DB`指定；与正式账户库路径相同或库中存在其他业务表时拒绝启动。
- 单请求10MiB、单游客20MiB、全库512MiB；创建和读写均限流，容量或保存失败不伪报成功。
- `node scripts/guest-status.mjs`提供本机只读汇总：身份数量、过期数量、负载字节、数据库文件大小和80%容量告警。无身份凭证或学习内容输出。
- 查看清理日志：`journalctl -u word-atlas.service`，关注`Guest cleanup`及`Guest cleanup failed`。清理报错时，接口仍根据时间拒绝已过期身份，需运维恢复物理删除。
- 现有正式备份是指定accounts.sqlite的SQLite在线备份，不是目录打包；新增游客库不在备份集合。主机/云平台整机快照无法由仓库代码排除，管理员需另外核对快照保留策略；本次不修改云控制台配置。
- SQLite使用DELETE事务日志及secure_delete，删除后的空间可复用，但不宣称磁盘取证级擦除；整机快照可能仍有旧副本。

## 使用限制与恢复

- 已暂存记录支持刷新、关页重开和服务重启恢复。离线/保存中会显示状态并提示离开风险；未提交的最后一次操作不承诺跨关页恢复。
- “返回入口”保留有效游客身份；“退出并清除游客数据”明确确认后撤销凭证并删除服务器记录。
- 多标签冲突不自动覆盖：先导出本页备份，再重新载入服务器版本。
- 正式账户登录/注册默认不导入。确认导入当前词库前先备份账户；复制后按版本清理源记录，其他游客词库仍保留至导入或到期。
- Cookie被清除或无痕窗口结束后不能恢复游客身份；临近失效时应导出或注册后确认导入。
