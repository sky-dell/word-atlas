# Word Atlas 注册与管理员授权会员：首版设计

日期：2026-10-28。状态：用户已批准，进入实施。

## 已确认与待确认

用户已明确：项目新增注册与会员机制；采用 **免费注册、管理员授权会员**。当前生产是公网 80 端口的 React 静态应用，Node.js 24.22.1 服务负责文件分发；学习记录主要在 IndexedDB，阅读与外观等附加数据在 localStorage，没有服务端账号或数据库。

以下权益、登录形式、会员期限和技术细节是实现者建议，用户尚未确认；批准本方案后作为首版实施范围。

## 用户获得的功能

| 身份 | 功能 |
| --- | --- |
| 游客 | 继续使用现有图鉴、学习、练习、书房与本地备份，记录保存在当前浏览器 |
| 普通注册用户 | 用户名/密码登录、修改密码、退出；浏览器内按账号隔离学习数据；查看会员状态 |
| 有效会员 | 普通用户功能 + 学习进度跨设备同步 + 云端备份与恢复 |
| 管理员 | 用户列表/搜索、开通/延期/取消会员、禁用/恢复账号、查看操作记录；管理员角色单独管理，不因会员开通而产生 |

建议不把现有免费学习功能直接收费或锁定。首版不接支付、兑换码、短信、邮件服务、第三方登录、公开排行榜或营销通知；也不重新包装已公开媒体为付费私有资源。

## 方案取舍

用户选择了管理员授权这一业务方案。技术上建议复用现有 Node 服务增加同源 `/api/`，采用 SQLite 存储账号、会话、会员及同步快照，匹配当前 2GB 单机部署。

- 独立 PostgreSQL/Redis 服务增加内存与运维成本，首版并发和数据量尚不需要。
- 外部托管身份服务会引入外部账号、密钥和授权依赖，当前没有相关配置。
- SQLite 方案没有新增公开数据库端口，后续可以迁移；账号、会话、会员授权不得存成前端可自行修改的身份数据。

选择数据库驱动、模块拆分和具体页面布局交给实现者；若使用 Node 内置 `node:sqlite`，应记录当前文档为 release candidate 的状态，锁定 Node24 并以数据库恢复/并发测试验证，不能宣传其已经正式稳定。

## 注册、登录与管理

1. 在「我的」增加账号和会员区域；注册/登录表单沿用当前视觉和手机适配。用户名 3–32 个 ASCII 字母/数字/下划线，忽略大小写去重；昵称可选、独立于唯一账号名。密码 12–128 字符，允许粘贴和密码管理器，不强制无意义的字符组合。
2. 注册成功直接登录，普通注册不得指定管理员、会员、到期时间或账号状态。数据库唯一索引处理并发重名。
3. 密码采用带随机盐和版本参数的慢哈希，建议异步 scrypt；使用恒定时间比较，不存明文密码。错误登录返回统一提示。限制注册/登录尝试，限制并发密码计算与请求体大小，避免压垮 2GB 主机。
4. 使用服务端持久会话和高熵随机 cookie；数据库只保存会话 token 的哈希。会话上限 7 天，登录轮换，退出撤销；改密/禁用账号撤销全部会话。管理员敏感操作要求重新验证密码，重新验证授权短期有效。
5. 唯一首个管理员由本机 CLI 创建，交互读取密码，不提供默认密码或公开初始化接口，也不把密码写进 Git、日志、命令行参数或聊天记录。普通网页管理员不授予/撤销管理员角色；后续管理员角色由本机 CLI 操作，防止失去最后一个管理员。
6. 首版不实现未经验证的“凭用户名找回密码”。普通用户改密需旧密码；忘记密码由管理员生成短期、一次性重置凭据，数据库只存摘要。管理员通过现有可信渠道手工交付，不自动对外发送消息。凭据只允许重设该用户密码，不能获取原密码；完成后撤销会话。
7. `#/admin` 为管理员页面；隐藏按钮只改善界面，所有实际管理操作由服务端验证角色、当前账号状态和近期密码验证。

## 会员规则

- 首版只有普通用户/会员两个等级；会员与管理员角色分开。
- 管理员可选择 30/90/365 天或永久。延期从 `max(当前时间, 原到期时间)` 开始；永久状态不能被误当作到期时间为空的普通账号。
- 服务端持久化授权状态、UTC 到期时间和操作记录；每次受限请求读取有效权限，不使用客户端时钟/备份 JSON 决定会员身份。
- 到期、取消或禁用后立即停止新的云端同步写入，不依赖用户下次登录。到期不删除学习数据；用户仍能下载自己的既有云端备份以避免数据被锁住。禁用账号不能访问账户接口，恢复后重新登录。
- 管理员操作记录包括操作者、目标账号、动作、前后期限与时间，不记录密码、会话 token、重置凭据或学习快照正文。

## 学习记录隔离与同步

现有存储按词库区分，尚未按账号区分。新增账号前必须同时处理 IndexedDB、localStorage 附加记录和跨标签通知，不能只在页面上显示用户名。

1. 游客及每个账号使用独立命名空间，云端也按用户及词库隔离。切换/退出时停止同步、取消旧请求、清空内存中的旧账号状态，再装载目标命名空间。多个标签页收到身份变化后同步切换，不能继续显示或上传旧用户记录。
2. 首次登录提供“导入本机游客记录”选择，不自动把共享电脑上的游客数据归入账号；不删除游客原始记录。HTTP 和 HTTPS 属于不同 origin，不能直接读取彼此的 IndexedDB；上线前提供当前 HTTP 页面的导出说明，HTTPS 页面使用既有 JSON 导入流程迁移，不能宣称数据自动迁移成功。
3. 云同步覆盖已完成的词卡进度、收藏、每日统计、练习记录、阅读位置及必要学习设置。未完成学习会话继续本机保存，首版不承诺跨设备接续到一半的题目；音频/图片等公共内容不按用户上传。
4. 云端保存版本号，上传须携带所读版本（CAS）；过期版本返回 409，显示冲突并允许先导出本机记录，再明确选择采用本机或云端。首版不静默覆盖、不叠加整份统计，不宣称自动合并冲突。
5. 自动同步有防抖，离线继续本地学习并显示未同步，网络恢复后检查版本。恢复云备份前先保留本地可导出副本。
6. 任何异步上传均携带预期账号标识，与服务端会话身份比对；查询/写入所有者始终取自会话。旧账号请求不能因共享 cookie 刚切换而写入新账号，旧响应也不能覆盖新账号内存。
7. 同步与备份使用有界、版本化 schema；单份请求上限 10 MiB、每账号每词库一个当前快照及最多 3 个历史备份；超过限制明确拒绝，不无限堆积。后续扩容按实际使用量调整。服务器备份仅指同主机持久化和本机备份，不能宣传已具备异地容灾。

## 后端、部署和 HTTPS

- `/api/auth/*`、`/api/account/*`、`/api/member/*`、`/api/admin/*` 为同源接口；具体资源命名在实施计划中确定。数据库位于 `/var/lib/word-atlas/`，不在 public/dist/导出包中。systemd 仅为该目录增加写权限，继续使用 word-atlas 专用用户。
- SQLite 使用参数化查询、事务、外键、迁移版本与 WAL；关闭动态扩展加载。服务启动先校验迁移，异常不得静默创建空账号库覆盖旧库。备份使用 SQLite 一致性备份接口，而非在线直接复制单个 .db 忽略 WAL。
- 所有身份接口 `Cache-Control: no-store`；Service Worker 明确绕过 `/api/`，禁止缓存账号资料、会员状态、备份与管理员响应，清理旧版可能遗留的账号相关缓存。静态词库与媒体保持原离线策略。
- 修改请求检查配置中的可信 Origin 和 CSRF token；不开放任意跨域凭证；限制 Host/代理头，只有配置的可信代理能影响客户端 IP 与 HTTPS 判断。前端身份持久化不存可读 bearer token。
- 当前 HTTP 入口不适合上线密码登录。建议先为公网 IP 配置受信任 HTTPS，使用 Certbot 的 IP 短期证书和自动续期/加载；也可使用用户已有受控域名。HTTPS 有效后，cookie 使用 Secure、HttpOnly、SameSite，80 端口保留入口并引导到 HTTPS，兼容旧 `/words/` 链接。
- 若云端 443 未放通或证书无法签发，先完成本地加密环境开发和测试；现有匿名 HTTP 学习网站继续正常运行，公网账号入口保持未启用。不能以 HTTP 明文密码或浏览器忽略自签名证书作为上线替代。该障碍须如实交付，而不是声称部署完成。
- 现有 AI-History-CSS 8080 维持独立站点；不要在该项目目录中暴露账号库或密钥。原静态镜像如继续发布，前端不得假设 8080 可处理同源账号 API，部署时明确账号功能的规范 origin。
- 定期一致性备份、有限保留与证书续期属于服务运维，落在 systemd timer 中并记录本机日志；不创建聊天自动化、不自动对外发通知。运行升级不得抹掉账号数据库。

## 验收

1. 注册/唯一用户名并发、正确/错误登录、会话持久化、退出与改密撤销。
2. 普通用户不能调用管理员接口、伪造会员或读取/修改其他用户数据；CSRF、注册限流及超大请求被拒绝。
3. 管理员开通、延期、永久、取消、禁用、恢复、一次性重置及操作记录可验证；成员到期判定使用可控测试时间。
4. 游客迁移、账号切换、跨标签、离线恢复、两设备版本冲突、旧请求跨账号竞态、备份恢复均不会串号/静默丢数据。
5. Service Worker 不缓存 API；HTTP 不提供生产密码登录；会话 cookie 正确加固，证书和续期已实际验证。
6. 服务重启后账号、授权及同步数据仍在；一致性备份恢复验证通过，存储目录不被静态服务读取。
7. 保留并运行现有自动化与浏览器回归，新增账号/会员/越权及同步场景，实际验证手机布局。
