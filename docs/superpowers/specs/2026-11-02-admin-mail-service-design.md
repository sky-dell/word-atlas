# 管理后台邮件服务配置

日期：2026-11-02

## 目标

在管理员控制台的左侧导航中增加“邮件服务”，允许管理员配置任意 SMTP 服务商、验证连接、保存配置并立即生效。

## 非目标

- 不支持 Resend、SendGrid 等 HTTP API 邮件服务。
- 不在浏览器、SQLite、日志、审计记录或状态接口中保存或返回 SMTP 授权码。
- 不提供明文查看授权码或导出完整邮件配置的功能。

## 选用方案

浏览器只与现有管理员 API 交互。管理器重新验证当前管理员密码后，由受限本地助手原子更新 root 私有的 `/etc/word-atlas/mail.env`。保存成功后 Web 进程使用助手返回的运行时配置替换内存中的邮件发送器，无需重启服务。

选择该方案是因为它保留现有权限边界，不把系统级配置写入 SQLite，同时能支持任意 SMTP 服务商。

## 页面

- 在“SSL 证书”之后新增“邮件服务”导航项，使用现有 Lucide 邮箱图标和米色后台样式。
- 页面顶部显示当前配置状态、服务地址、登录账号和发件地址，不显示授权码。
- 配置区使用现有 `admin-card` 和表单控件，包含：SMTP 主机、端口、安全模式、登录账号、授权码、发件邮箱、发件人名称。
- 安全模式提供隐式 TLS 和 STARTTLS，两者都强制校验证书并至少使用 TLS 1.2。
- 授权码为只写字段。已配置时留空表示保留原授权码。
- 操作按钮为“验证连接”和“保存配置”。两个操作都要求管理员重新输入当前密码。
- 不显示功能介绍、使用说明、安全横幅或冗余提示文案。仅显示字段校验、操作状态和必要的错误信息。
- 320、390、768、1280 和 1440 宽度下不产生横向溢出，表单与状态区保持现有后台的密度和层级。

## API

### `GET /api/admin/mail`

仅管理员可访问，返回非敏感状态：

```json
{
  "configured": true,
  "host": "smtp.example.com",
  "port": 465,
  "security": "tls",
  "user": "sender@example.com",
  "from": "sender@example.com",
  "fromName": "词与远方",
  "secretConfigured": true
}
```

### `POST /api/admin/mail/test`

请求体：

```json
{
  "host": "smtp.example.com",
  "port": 465,
  "security": "tls",
  "user": "sender@example.com",
  "password": "optional-when-updating",
  "from": "sender@example.com",
  "fromName": "词与远方"
}
```

管理器完成重新认证后，服务端使用候选配置执行 SMTP 握手、身份认证和 TLS 校验，返回连通状态与耗时，不改变当前配置。

### `POST /api/admin/mail`

请求体与测试接口相同。成功后原子写入 root 私有配置文件，保留现有 `MAIL_CODE_SECRET`，替换内存中的邮件发送器，并写入不含授权码的审计记录。

## 安全约束

- 所有接口要求管理员角色、可信 Origin、CSRF、管理员重新认证和独立限流。
- 主机名解析结果不得为回环、私网、链路本地、组播或未指定地址；连接使用已经校验的解析结果。
- 强制 TLS 证书校验和 TLS 1.2 以上协议，禁止把 SMTP 错误或授权码透传到响应与日志。
- 配置文件必须为 root 私有普通文件，拒绝符号链接和非安全权限；写入采用临时文件、`fsync` 和原子重命名。
- 已保存授权码不能被读取；空授权码只在已有配置存在时表示保留。
- 概览中的“邮件服务”状态随动态配置立即更新。

## 验证

- 服务端测试覆盖权限、重新认证、CSRF、限流、输入校验、私网地址拒绝、TLS 要求、只写授权码、原子写入、动态启用和审计脱敏。
- 浏览器测试覆盖导航、表单、连接测试、保存、重新认证、响应式布局和无冗余提示文案。
- 运行完整 `npm test`、服务端测试和生产构建。
